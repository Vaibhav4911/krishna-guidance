# Krishna Guidance

A production-ready spiritual guidance platform inspired by Bhagavad Gita teachings, built with a Next.js frontend and FastAPI backend.

## Tech stack

- Frontend: Next.js 14, React 18, TypeScript, Tailwind CSS, shadcn-style components
- Backend: FastAPI, Python 3.12+
- Database: PostgreSQL
- Vector DB: Qdrant
- Cache: Redis
- Auth: email/password signup and login with revocable JWT sessions
- AI inference: self-hosted vLLM with open-weight models; no paid AI API required

## Current implementation status

This workspace now contains:

- Landing page and interactive chat UI shell
- FastAPI backend with modular routes for health, authentication, guidance, journaling, and admin
- Email/password authentication with scrypt password hashes and revocable JWT sessions
- Protected profile, chat, and admin endpoints
- SQLAlchemy model definitions for users, conversations, journal entries, favorites, and source records
- Chapter-level keyword retrieval over an attributed English Gita source
- Verse-level Sanskrit source corpus with revision-specific citations
- Self-hosted multilingual chat and semantic retrieval pipeline
- Docker Compose for local app stack

### Scripture corpus prototype

The API uses Project Gutenberg eBook #2388, Sir Edwin Arnold's poetic English translation, as a chapter-level retrieval signal. It is not shown as a citation or mapped to individual verses. For Hindi questions, the configured local model translates the query into English for retrieval; the translated query is not shown to users. Chapter matches are combined with Sanskrit verse embeddings, and every displayed śloka is resolved from the separate 700-verse Sanskrit Wikisource corpus. This improves multilingual recall but is not a substitute for a reviewed, verse-aligned English/Hindi translation corpus. The Sanskrit text is contributor-transcribed and is not an independently reviewed critical edition.

Authenticated Ask Krishna chat and `/api/v1/rag/search` accept English and Hindi. User-facing guidance is intended to be short, simple, and in the selected language; Sanskrit answers are disabled. The original Sanskrit śloka is shown separately with a simple meaning and a detailed explanation. These are plain-language reflections, not authoritative translations; chapters 2:7, 2:47, 3:17, 12:9, and 18:63 have curated renderings, while other explanations are generated by the local model. Recent chat turns are sent as context for follow-up questions; clarification and additional-verse requests avoid previously cited passages and ask for fresh, non-repetitive responses. The transcript is kept in browser memory and is not saved by the chat endpoint.

The local model runtime and model weights have no per-request API charge: Qwen3 4B is used for chat and Hindi query translation, and BGE-M3 (MIT) is used for embeddings. See the [Qwen3 model card](https://huggingface.co/Qwen/Qwen3-4B) and [BGE-M3 model card](https://huggingface.co/BAAI/bge-m3). Review model licenses and continue evaluating Hindi/Sanskrit retrieval and response quality before launch. GPU servers, bandwidth, and hosting may still cost money. Production deployments should use private inference endpoints behind the API network/firewall.

The local developer setup uses Qdrant's embedded persistent mode and does not require Docker. Production deployments should configure a Qdrant server with `QDRANT_URL` and `QDRANT_API_KEY`.

Corpus provenance, attribution, and ingestion instructions are documented in `apps/api/data/corpora/edwin_arnold/README.md` and `apps/api/data/corpora/wikisource_sanskrit/README.md`.

## Local development

### Frontend

```bash
npm install
npm run dev
```

### Backend

With PostgreSQL installed and the `krishna_guidance` database/user created, configure `apps/api/.env` from `.env.example`. Put your local database password in `DATABASE_URL`; do not commit `.env`.

```bash
cd apps/api
python -m venv .venv
.venv\Scripts\Activate.ps1  # Windows PowerShell
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Users can create an account with an email and password or sign in to an existing account. Passwords must contain at least eight characters and are stored as scrypt hashes. Email ownership is not verified in this local prototype; use HTTPS and add a verified recovery flow before production.

### Run migrations

```bash
cd apps/api
alembic revision -m "describe change"
alembic upgrade head
```

The application does not create tables at startup. Run Alembic migrations before starting the API.

Run backend tests with:

```powershell
pip install -r requirements-dev.txt
pytest
```

### Local AI setup (Windows, CPU-friendly)

For local testing, use [Ollama for Windows](https://ollama.com/download/windows) with Qwen3 4B and the multilingual BGE-M3 embedding model. This runs on your computer and does not use a paid inference API. It may be slow on CPU; Ollama can also use a supported local GPU automatically, without cloud GPU charges.

The app separates three jobs:

| Component | Local choice | Purpose |
|---|---|---|
| Chat | Qwen3 4B | Produces a short, simple English or Hindi reflection inspired by the Gita. It is not Lord Krishna and does not generate the cited scripture. |
| Embeddings | BGE-M3 | Finds Sanskrit source verses relevant to English or Hindi questions. |
| Index | Qdrant | Stores vectors and verse IDs. The app displays Sanskrit text from its verified corpus. |

#### 1. Install Ollama and download models

Install Ollama, then open a **new Command Prompt** and run:

```cmd
ollama pull qwen3:4b
ollama pull bge-m3
ollama list
```

These are model downloads and can take several minutes and a few gigabytes of disk space. Ollama normally runs in the background after installation. If it is not running, start the Ollama application from the Windows Start menu.

Check that its local server responds:

```cmd
curl.exe http://127.0.0.1:11434/api/tags
```

#### 2. Configure the existing API `.env`

Edit `apps\api\.env` without replacing your PostgreSQL or JWT settings. Set the following values:

```dotenv
LLM_PROVIDER=ollama
LLM_CHAT_BASE_URL=http://127.0.0.1:11434
LLM_EMBEDDINGS_BASE_URL=http://127.0.0.1:11434
LLM_API_KEY=
LLM_CHAT_MODEL=qwen3:4b
LLM_EMBEDDING_MODEL=bge-m3
LLM_EMBEDDING_DIMENSIONS=1024
QDRANT_URL=
QDRANT_API_KEY=
QDRANT_COLLECTION=bhagavad_gita_sanskrit
```

Both Ollama models use the same local server. Keep it on `127.0.0.1`; do not expose port `11434` to the internet. Remove any old `OPENAI_*` example lines; the app no longer uses them.

#### 3. Create the local verse index

From Command Prompt:

```cmd
cd apps\api
python -m app.scripts.ingest_sanskrit_embeddings
```

This sends all 700 Sanskrit verses to your local BGE-M3 model and stores the vectors in Qdrant under `apps\api\data\qdrant\`. It can take time on CPU. Stop the API first if it already has the local Qdrant database open. Use `--replace` only when intentionally rebuilding the index.

#### 4. Run and test chat

Start the API and web app using the [local development steps above](#local-development). Ask a short question in English or Hindi, then continue with follow-up questions in the same chat. The API retrieves verse candidates; the chat model writes a simple response; the UI displays the original Sanskrit with its meaning and explanation. If the model or index is unavailable, the API reports an error instead of fabricating a response or citation.

#### Production note

This local setup is for functional and quality testing, not high-concurrency hosting. Later, the API can point at a private model server, but speed and concurrency must be measured on the target hardware. Open-weight models have no per-request API charge; server hosting, if used, may still cost money.
